# P22-A — Native Rust library protocol codecs

Tested implementation: `08a802e53026ff6c07fb07b0bd20837edc21908a`.
State: implemented, coordinator integration/remote CI pending; P22 as a whole is not complete.
Owner explicitly authorizes a usable Rust HomeKit library, including maintaining an
existing library or building missing functionality with maintained crypto primitives.
No runtime server, discovery advertiser or pairing is introduced in this stage.

## Interfaces and provenance

`transport_homekit::codec::tlv::{Tlv,encode,decode}` bounds pairing messages to 8192
bytes and 256 logical items, reassembles canonical 255-byte fragments, validates
separators and refuses truncated/ambiguous duplicate fields without panicking.
Unknown tags are preserved for higher-level state machines to handle explicitly.

`codec::record::{RecordCipher,record_length}` handles exactly one authenticated
IP record at a time: length<=1024 (including a valid zero-length authenticated
frame), two-byte little-endian AAD length, four zero nonce bytes followed by the
little-endian u64 directional counter and a 16-byte authentication tag. Invalid
input/authentication poisons the receiver; counters cannot wrap and cipher state
is deliberately not Clone/Debug. The adapter must provide complete frames, preserve
partial/coalesced TCP data, retain partial writes and derive unique directional
session keys. Caller key ownership/erasure remains explicit; no reuse/reset allowed.

Primitive: chacha20poly1305=0.11.0 with alloc+zeroize, no own crypto primitives.
Context7 resolution/query succeeded; primary RustCrypto API and registry version
verified. Protocol references:
[Apple IP security framing](https://github.com/apple/HomeKitADK/blob/fb201f98f5fdc7fef6a455054f08b59cca5d1ec8/HAP/HAPIPSecurityProtocol.c),
[Apple session counters](https://github.com/apple/HomeKitADK/blob/fb201f98f5fdc7fef6a455054f08b59cca5d1ec8/HAP/HAPSession.c),
[Apple TLV tests](https://github.com/apple/HomeKitADK/blob/fb201f98f5fdc7fef6a455054f08b59cca5d1ec8/Tests/HAPTLVTest.c),
[RustCrypto](https://docs.rs/chacha20poly1305/0.11.0/chacha20poly1305/).
No upstream source is copied into the product.

`fixtures/homekit/record-vector.json` uses a fictional deterministic key and
four independent vectors from Python cryptography 49.0.0 ChaCha20Poly1305: ordinary
HTTP bytes, 1024-byte payload, a later counter, and an authenticated empty frame.
Python/cryptography is only the fixture-generation tool, never a runtime dependency.
No physical or private household traffic was captured.

## Evidence and limits

Five behavior tests were observed failing against no-op codecs before implementation.
Counter-exhaustion separately failed with wrapping arithmetic before its guard.
Primary Apple code showed zero-length authenticated frames are accepted; the
new zero-length behavior test failed before the implementation was corrected.
The strict Clippy constant-chunk lint was fixed in the test fixture decoder.
All six codec tests and all four workspace checks passed locally (22 workspace
tests on the isolated baseline). Independent worker read-only review found no
actionable defect; the later zero-length correction is supported by the Apple source.

Missing: pairing/setup/verify, authenticated route permissions, persistent pairings,
revocation, TCP buffering/write behavior, bounded server resources and shutdown,
actual Apple Home interoperability/security/hardware review. This stage does not
approve any backend, launch the rejected P04 bridge or prove complete HAP conformance.
Continue the bounded native library stages and integration with the Store/router;
do not replace HomeKit with a UI-only delivery or call this a complete library.
